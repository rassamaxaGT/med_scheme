# Документация проекта: МедРисунок - УЗИ Редактор (MedRisunok)

Данный документ объединяет в себе Техническое задание (ТЗ) и техническое описание Архитектуры проекта для передачи заказчику.

---

## ЧАСТЬ 1: Техническое задание (ТЗ)

### 1. Описание проекта
**«МедРисунок - УЗИ Редактор»** — это специализированное кроссплатформенное графическое приложение, разработанное для врачей УЗИ-диагностики, гинекологов и хирургов. 
Приложение работает как «медицинская раскраска», позволяя врачу быстро наносить специфические патологии и маркеры на стандартизированные анатомические схемы или загруженные снимки УЗИ. Приложение работает полностью локально, не собирает и не хранит персональные данные пациентов (ПДн), что исключает риски нарушения конфиденциальности.

### 2. Поддерживаемые платформы
*   **Планшеты и смартфоны:** Android / iOS / HarmonyOS (особый упор на поддержку стилусов).
*   **Персональные компьютеры и ноутбуки:** Запуск в любом современном веб-браузере (Web).

### 3. Функциональные требования

#### 3.1. Работа с холстом и изображениями
*   **Импорт фоновой схемы:** Возможность загрузить изображение УЗИ-снимка или базовой анатомической схемы из галереи устройства (на мобильных) или выбрать файл с диска (на ПК/Web).
*   **Удаление фона:** Возможность очистить фоновое изображение для рисования на чистом белом листе.

#### 3.2. Специализированный медицинский инструментарий (Маркеры)
*   **Кисть «Колючая проволока»:** Для разметки областей эндометриоидного инфильтрата.
*   **Кисть «Паутина»:** Для указания спаечного процесса брюшной полости.
*   **Шоколадный овал:** Залитая полупрозрачная область коричневого цвета для разметки эндометриомы.
*   **Розовый овал:** Полупрозрачная область бледно-розового цвета для обозначения миомы матки.
*   **Штамп «ВМС» (Спираль):** Быстрое нанесение знака внутриматочной спирали.
*   **Штамп «Очаг» (Пятно):** Разметка эндометриоидных очагов.
*   **Стрелки с текстом:** Инструмент указания стрелки с открывающимся диалоговым окном для ввода аннотации (текст автоматически масштабируется и отображается у основания стрелки).
*   **Обычная кисть и Ластик:** Для произвольного рисования и удаления штрихов.

#### 3.3. Жесты, масштабирование и поддержка стилуса
*   **Инструмент «Перемещение» (Move):** Возможность выделить любой нарисованный ранее объект (линию, овал, стрелку), переместить его по холсту или изменить его размеры.
*   **Zoom & Pan:** Масштабирование и перемещение всего холста двумя пальцами (pinch-to-zoom) для детальной проработки мелких зон.
*   **Поддержка стилуса:**
    *   *Palm Rejection (Игнорирование ладони):* При рисовании пером касания холста ладонью или другими пальцами автоматически игнорируются для избежания ложных штрихов.
    *   *Чувствительность к нажатию:* Толщина линии динамически меняется в зависимости от силы давления пера стилуса.

#### 3.4. Сохранение, загрузка и экспорт
*   **Выбор рабочей директории:** 
    *   *На Android:* Однократный запрос папки через Storage Access Framework (SAF) с сохранением постоянных прав доступа (persistable permission).
    *   *На iOS:* Автоматическое сохранение в песочницу приложения с включенным iTunes File Sharing (файлы видны в стандартном приложении «Файлы»).
    *   *На Web:* Автоматический экспорт и импорт файлов напрямую через загрузки браузера.
*   **Формат проекта `.meddraw`:** Проприетарный формат файла (ZIP-архив), содержащий фоновое изображение (`background.png`) и файл разметки (`project.json`) с векторными координатами и параметрами всех действий. Проект можно переносить между устройствами и редактировать повторно.
*   **Экспорт готовой схемы:** Сохранение объединенного плоского изображения (фон + разметка) в формате PNG в галерею устройства или скачивание на компьютер.

## ЧАСТЬ 2: Архитектура проекта (Architecture)

Проект спроектирован по канонам **Clean Architecture (Чистой архитектуры)** с разделением ответственности по слоям (Feature-First подход), что обеспечивает независимость UI от файловой системы и платформы.

### 1. Архитектурные слои
*   **Domain (Домен):** Содержит бизнес-сущности разметки (DrawAction), описание проекта (ProjectData) и абстрактный интерфейс репозитория (ProjectRepository). Этот слой полностью автономен и не зависит от фреймворков.
*   **Data (Данные):** Отвечает за сериализацию моделей (DrawActionModel) и реализацию сохранения/загрузки. Платформенно-зависимый код вынесен в изолированные файлы реализации, подключаемые на этапе компиляции.
*   **Presentation (Представление):** Содержит BLoC-контроллеры управления состоянием (DrawBloc, ProjectBloc), интерактивный виджет холста (CanvasWidget) и плавающий тулбар (FloatingToolbox).

### 2. Кроссплатформенность и условная компиляция (Conditional Imports)
Для одновременного запуска на мобильных девайсах (где требуется прямой доступ к диску, Android SAF и iOS Sandbox через `dart:io`) и в браузере (где нет файловой системы и `dart:io` вызывает ошибки) применена технология **Conditional Imports**.

1.  **Репозиторий проектов (ProjectRepository):**
    *   Регистрация в DI (injection.dart) идет через абстрактный провайдер.
    *   При сборке под Android/iOS/Windows подключается `project_repository_impl.dart`, работающий с диском и SAF.
    *   При сборке под Web подключается `project_repository_web.dart`, работающий с ZIP в оперативной памяти и инициирующий скачивание файлов через теги браузера.
2.  **Загрузчик изображений (image_loader.dart):**
    *   Абстрагирует UI от загрузки фонов.
    *   На IO-платформах читает байты файла с диска напрямую.
    *   На Web преобразует загруженную картинку в Blob URL в памяти браузера (`blob:http://...`) и рендерит её стандартными веб-методами.
3.  **Взаимодействие с API браузера (web_helper.dart):**
    *   Использует JS-интероп (`dart:html` / `package:web`) на вебе для вызова стандартных диалогов скачивания и генерации Blob-ссылок. На мобильных устройствах подменяется пустыми заглушками без вызова ошибок компиляции.

### 3. Отрисовка холста (Рендеринг)
Отрисовка разметки выполняется в классе `CanvasPainter`:
*   Используются нативные методы `Canvas` Flutter.
*   Эффекты инфильтратов и спаек вычисляются динамически с помощью `ui.PathMetrics`, которые разбивают нарисованные кривые линии на равные отрезки и рисуют перпендикулярные штрихи («иголки») или соединяющие нити («паутину») с математической точностью, сохраняя стабильный FPS.
*   Текстовые аннотации стрелок рисуются в экранном пространстве поверх масштабируемого холста, чтобы размер букв и стрелок всегда оставался читаемым и четким вне зависимости от масштаба приближения.
