### БЛОК 1: Проект Технического задания (ТЗ) v3.0

**1. Описание проекта**
Профессиональное приложение-редактор для врачей УЗИ-диагностики («медицинская раскраска»).
**Главная ценность:** Быстрое ручное нанесение специфических маркеров и патологий на стандартизированные анатомические схемы или загруженные снимки УЗИ.
**Область применения:** Исключительно ручное графическое редактирование и разметка сканов (снимков УЗИ) пользователем. Приложение не выполняет автоматического сопоставления, совмещения изображений, 3D-рендеринга на основе срезов или интеллектуальной/автоматической диагностики.
**Целевая аудитория:** Врачи УЗИ, гинекологи, хирурги.
**Особенности:** Приложение не хранит ПДн (персональные данные пациентов) и распространяется путем ручной установки (Ad-Hoc / APK).

**2. Поддерживаемые платформы**
- Планшеты (приоритет) и смартфоны. ОС: Android / HarmonyOS (фокус из-за стилуса Huawei) и iOS.

**3. Роли пользователей**
- Локальный пользователь (Врач).

**4. Функциональные требования (User Stories)**

*Эпик 1: Работа с холстом и базовыми изображениями*
- Выбор анатомической схемы из предустановленной библиотеки.
- Импорт базовой схемы из галереи устройства.
- **Идентификация пациента:** Локальное текстовое поле ввода Фамилии или ID пациента. Строка отображается на холсте, сохраняется в проект `.meddraw`, встраивается в экспортируемый PNG/PDF, а также автоматически используется в качестве префикса в имени сохраняемого файла проекта (например, `ID_дата.meddraw`) и изображения (например, `ID_дата.png`).

*Эпик 2: Инструменты рисования (Core Feature)*
- **Базовые инструменты:** Отмена (Undo), Повтор (Redo), Ластик, обычная кисть.
- **Предустановленные маркеры патологий (адаптировано из Sonocontreras):**
  - *Эндометриоз:* Глубокий узел (красный круг), Эндометриома (коричневый круг), Поверхностный очаг (желтый круг/звездочка), Линия спаек (зеленая линия/пунктир), Линия расстояний (пунктир с текстовой аннотацией). См. визуализацию: ![Визуализация обозначений карты эндометриоза](file:///d:/projects/med_scheme/assets/images/endo_legend.png)
  - *Миомы матки (с цветовым кодированием FIGO и ID миомы в круге):* Субмукозные (розовый круг), Интрамуральные (синий круг), Субсерозные (зеленый круг), Другие/шеечные (серый круг), Гибридные миомы, Линии расстояния от миомы до серозы / полости эндометрия. См. визуализацию: ![Визуализация обозначений классификации миом FIGO](file:///d:/projects/med_scheme/assets/images/myoma_legend.png)
- **Дополнительные маркеры:** ВМС (Т-образный графический штамп спирали).
- **Пользовательские инструменты:** Создание/импорт новых штампов из PNG.

*Эпик 3: Работа со стилусом и жестами*
- Поддержка стилуса: игнорирование касаний ладонью (Palm rejection), реакция на силу нажатия.
- Масштабирование холста (Zoom/Pan) пальцами.

*Эпик 4: Сохранение и файловая система*
- **Выбор директории:** При первом запуске приложение запрашивает у пользователя папку на устройстве для хранения проектов. В дальнейшем все файлы сохраняются туда автоматически.
- **Формат проекта:** Сохранение в проприетарном формате (Zip-архив с расширением `.meddraw`, содержащий фон и JSON с векторами действий) для возможности переноса на другое устройство и доработки.
- **Экспорт:** Сохранение готовой плоской схемы (JPEG/PNG) в галерею.

**5. Нефункциональные требования**
- Архитектура Clean Architecture + BLoC.
- Полная офлайн-работа. 
- Планшетно-ориентированный UI.

### БЛОК 2: Архитектурный план и фокус для Flutter-разработчика

Привет! План отличный, `perfect_freehand` отправляем в бэклог, ZIP-контейнер утверждаем. Но твое решение по файловой системе требует особого внимания из-за современных ограничений ОС.

**1. Bottleneck: Разрешения на доступ к папке (Scoped Storage / Sandbox)**
Ты предложил: *"При первом запуске запросить путь для сохранения и использовать эту папку"*.
**В чем проблема:** 
- На **Android 11+** действует Scoped Storage. Если ты запросишь папку через обычный `file_picker`, ОС выдаст тебе *временный* URI. При перезапуске приложения ты потеряешь право писать в эту папку без повторного запроса.
- На **iOS** жесткая песочница (Sandbox). Ты вообще не можешь писать в произвольные папки пользователя, кроме папки самого приложения.

**Решение для тебя:**
- **Для Android:** Тебе придется использовать Storage Access Framework (SAF). Обрати внимание на пакет `shared_storage`. Он позволяет один раз запросить у пользователя доступ к директории (через `ACTION_OPEN_DOCUMENT_TREE`), получить постоянный URI и сохранить право (persistable permission) на запись в эту папку навсегда.
- **Для iOS:** Лучший путь — использовать `getApplicationDocumentsDirectory()`, но в `Info.plist` включить ключи `UIFileSharingEnabled` (Application supports iTunes file sharing) и `LSSupportsOpeningDocumentsInPlace`. Тогда папка твоего приложения станет видимой в стандартном приложении "Файлы" (Files) на iPad/iPhone, и врач сможет оттуда копировать файлы проектов или перекидывать по AirDrop.

**2. Архитектура BLoC и Холста**
Напоминаю: старайся не грузить BLoC координатами.
- `DrawBloc` хранит: `List<DrawAction> history`, `ToolType currentTool`, `Color currentColor`.
- `CustomPaint` / `GestureDetector` работают с локальным состоянием текущей линии (штриха). Когда пользователь отрывает стилус (`onPanEnd`), локальная линия превращается в `DrawAction` и улетает в `DrawBloc` через `context.read<DrawBloc>().add(AddStrokeEvent(action))`.

**3. Подготовка к старту**
- Можешь закладывать базовую структуру проекта (Clean Arch) и настраивать DI.
- Для Zip-архивации файлов используй пакет `archive` (запускай архивацию в изоляте через `compute`, чтобы не фризить UI во время сохранения тяжелых картинок).
- Изучи класс `PathMetrics` — это твой главный инструмент для "колючей проволоки" и "паутины".
